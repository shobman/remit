Move between AI providers

A registry you write names which harness and model each role sits on, so one model can build and a rival can judge — nothing is raised on a seat you did not register, and nothing falls back. The item moves between them without copy and paste — five harnesses run remit's builders.

Every harness

Five harnesses, one work surface.

The installer puts the same six conventions where each of them looks, and bin/remit-invoke demonstrates CLI invocation for all five. Open whichever one you feel like this morning: the item on the other side is the same item.

Claude Code

Every context is raised through the CLI by one script, never through the harness's own sub-agent tool — a shipped hook refuses that, so the registry decides every seat. The conventions land in .claude/skills/.

Codex

Nothing bespoke: the same six conventions in the path it reads, the same seam, the same draft pull request at the end.

Pi

Serves whatever the providers configured on your own machine are ready to run. A dispatch is refused unless that machine's own catalogue lists the id.

Devin

Needs no path of its own, discovering the installed conventions natively. An unknown model id is turned away before the run starts.

Copilot CLI

The only one here that takes a reasoning effort as well as a model, and checks both before it bills anything. A hook written for the run keeps its builder off git and gh, and the dispatch tests that before it trusts it. There is no read boundary beyond that: the builder runs on your own machine under your own credentials, and every pull request says so.

The README's model list was read on 21 August 2026. The models available to you depend on your subscription, and vendors change their model offerings often. Not every model is available at every subscription level. remit does not maintain a compatibility matrix, so check the sources beside the list for what your subscription includes today. The pull request records which model actually served each run.
