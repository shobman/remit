remit VERSION 0.3.18

For the person who owns the result

Let AI work without keeping you on call.

Everyone counts an AI's tokens and bills its time. Nobody counts the attention of the person who has to judge, decide and own the result, though it is the scarcest resource in the work. remit records the work and lets it continue or wait without you, and brings you back only for the judgements that are genuinely yours.

The shipping problem

AI can produce code faster than you can judge it.

A generated change still needs a boundary and a person willing to review and own the result.

AI creates work you did not ask for

One request becomes several decisions about what the task should include, each of them yours to notice and unwind.

Review falls behind the output

Generation outruns the capacity to review and ship it. The decision to ship still lands with you.

Decision volume wears you down

A long queue of decisions makes it harder to keep judging well. Time on task adds to the strain.

Your attention

It asks for a word at three moments, and nothing between them.

One to start, one at each stop that is genuinely yours, one to end. Everything else is housekeeping, and it happens without you.

One word to start

The brief is in your words, filed as you said it, with one word for how far the work may go before it waits for you. Nothing raised by remit edits it, rewrites it, or fills in what you left out.

A stop only where one is needed

A question only you can answer. A rule you wrote that said hold. A run that failed four times. Each is one row on the record, waiting; nothing is pushed at you, and nothing proposes what you should do about it.

Nothing to reconstruct

Weeks later, in a new session, in a different harness, the item reads the same. The context that matters stays with the work, so no chat is ever the memory for it.

A verdict, not a builder's account of itself

A fresh context that did not write the work judges it against your brief and your rubrics before it reaches you. Seat that judge on a rival model family, and read a verdict instead of a self-report. Agreement is never verification, so the proof a builder ran is kept where the judge can read it.

A number for what it cost you

The words you typed and the words said back to you, per session and per item, never summed into a score. Every context raised is on the record with its harness, its model, and its cost where the harness reports one.

The boundary

What it never does.

Never on your behalf

It never starts work, merges a pull request, reads a check, edits your brief, or closes an item. Closure is yours, and it is an attention boundary, not an acceptance.

Never on a seat you did not name

A registry you write says which harness and model each role sits on. Nothing is raised elsewhere, nothing falls back when a seat refuses, and every refusal happens before anything is billed.

Never out of reach

One command ends a running chain and every context it raised, discards the in-flight tree, and leaves the item where it last stopped. A context starts with an emptied environment: no token or key crosses, and its CLI logs in as you through its own configuration directory.

One item, end to end

The state stays visible, and a stop reaches you as one row.

Four stages, three gates. You say how far it may go; it stops at that stage, or earlier where a word of yours is needed, and the record says which.

One command files your answer in your words and the chain resumes where it stopped. A conductor may answer for you only under an elevation you wrote, at most twice per item; the third is yours.

Every harness

Use the agents you already pay for.

The installer puts the same seven conventions where each of the five looks, and one seam raises a context on any of them. Open whichever you feel like this morning: the item on the other side is the same item, with its history. What holds a context in place differs by harness, and each pull request says which applied.

Claude Code

Every context is raised through the CLI by one script, never through the harness's own sub-agent tool: a deny flag and a hook written for the run refuse it. No enforced read boundary — a context runs on your machine under your login.

Codex

The one seat with an enforced sandbox: its own workspace and nothing else, read back from the run's own header after every run and refused on a downgrade.

Pi

Serves whatever the providers on your own machine are ready to run; a dispatch is refused unless that machine's catalogue lists the id. Built-in tools only, extensions off. No enforced read boundary.

Devin

Discovers the installed conventions natively. An allow list written for the run ends the run on anything outside it, and an unknown model id is turned away before the run starts. No enforced read boundary.

Copilot CLI

The only one here that takes a reasoning effort as well as a model, and checks both before it bills anything. A hook written for the run keeps its builder off git and gh in any wrapping, and a throwaway run tests that before the real one. No enforced read boundary.

Nothing raised by remit carries your API keys or tokens; each CLI logs in as you through its own configuration directory. The README states the boundary in full, and its model lists carry the date they were read.

Install

Bring the discipline into your repository.

Three scripts, the conventions, one section of AGENTS.md and a folder for the work, every file recorded in a manifest. No service, no daemon, nothing to operate. The README explains how to inspect or pin the installer before you run it.

AIDOS is separate from remit and complementary by design: it helps teams establish that work is warranted before development starts. remit sits on the engineering side, bounded by AIDOS or completely adjacent to it.

The housekeeping stays out of your way.

The record keeps the work, so it can wait without getting lost. A fresh context judges it before it reaches you. The creating and the deciding stay with you, and they reach you only where a word of yours is needed.
